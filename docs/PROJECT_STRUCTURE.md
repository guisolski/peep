# peep - Project Structure

## Overview

peep is a **single Go module** (`github.com/guisolski/peep`), not a monorepo. There
is no `internal/` — every package is importable, but only `main` is meant to be
consumed as a binary. The root package holds the entry point and the headless-mode
dispatcher; everything else lives in small, single-purpose packages.

---

## Top-Level Layout

```
peep/
├── main.go        # entry point: flag parsing, input loading, bubbletea startup
├── cli.go          # headless dispatch for --query/--schema/--llm
├── input/          # source detection (file / stdin / clipboard / interactive paste)
├── model/          # application state: App root model, view sub-models, JSON node, export, jq
├── clipboard/       # clipboard write helper (swappable in tests)
├── ui/              # terminal-adaptive lipgloss color styles
├── testdata/        # sample JSON fixtures used by tests
├── docs/            # this documentation
├── Formula/         # Homebrew formula, auto-generated by the release workflow — do not edit by hand
├── go.work           # not present; single-module repo
├── go.mod
├── Makefile
└── .goreleaser.yml
```

## Packages

### main (root)

| Item | Value |
|------|--------|
| **Description** | CLI entry point and headless-mode dispatch |
| **Entry point** | `main.go` |
| **Files** | `main.go` (flags, input loading, Bubble Tea startup), `cli.go` (`headlessMode`, `runHeadless`, `runQuery`, `printExport`) |

`main.go` parses flags, resolves `--query`/`--schema`/`--llm` into a single headless
mode via `headlessMode` *before* loading input — so a flag-usage mistake (e.g. two
mutually exclusive flags) fails fast instead of risking a hang on the interactive
paste prompt. Input is then loaded once via `input.Load` and handed either to
`runHeadless` or to a new `model.App` running under `tea.NewProgram`.

### input/

| Item | Value |
|------|--------|
| **Description** | Detects and reads the JSON source |
| **Key file** | `input/load.go` |

`Load(args, pasteFlag)` resolves the source in priority order: explicit file
argument → piped stdin (detected via `isTerminal`) → `--paste` flag (reads the
system clipboard) → interactive paste (blocks on stdin until `Ctrl+D`). Returns a
`Result{Data, Source, Name}`.

### model/

| Item | Value |
|------|--------|
| **Description** | Application state and all TUI view logic |
| **Root model** | `model/app.go` — `App`, implements `tea.Model` |

| File | Purpose |
|------|---------|
| `app.go` | `App` root model: mode switching, global keybindings (quit, multi-key sequences like `gg`/`yy`), status bar, clipboard actions |
| `submodel.go` | `SubModel` interface implemented by every view mode |
| `tree.go` | `TreeModel` — collapsible tree view, cursor movement, expand/collapse |
| `graph.go` | `GraphModel` — Miller-column (depth-panel) layout |
| `raw.go` | `RawModel` — scrollable pretty-printed JSON viewport |
| `search.go` | `SearchModel` — fuzzy key/value search over the flattened tree |
| `filter.go` | `FilterModel` — live `jq` filter input, renders results via `RawModel` |
| `node.go` | `Node` — parsed JSON tree (`ParseJSON`, `Path`, `Summary`, `ToInterface`) |
| `export.go` | `Node.Schema()` and `Node.CompactYAML()` — LLM-friendly export formats |
| `jq.go` | `parseJQ`, `EvalAllJQ` — shared `gojq` evaluation used by both the filter view and `--query` |

### clipboard/

| Item | Value |
|------|--------|
| **Description** | Thin wrapper around `github.com/atotto/clipboard` |
| **Key file** | `clipboard/clipboard.go` |

Exposes `Copy(s string) error` via a package-level `WriteFunc` variable, so tests can
swap in a fake and never touch the real OS clipboard.

### ui/

| Item | Value |
|------|--------|
| **Description** | Shared `lipgloss` styles |
| **Key file** | `ui/colors.go` |

Adaptive colors (`lipgloss.AdaptiveColor`) that pick a light or dark variant based on
the terminal background, plus shared box/status-bar/mode-tag styles used across
`model/`.

## Where is X?

| If you are looking for… | Path |
|--------------------------|------|
| CLI flag parsing and startup | `main.go` |
| Headless mode resolution (`--query`/`--schema`/`--llm`) | `cli.go` (`headlessMode`, `runHeadless`) |
| Input source detection (file/stdin/clipboard/paste) | `input/load.go` |

| View-mode interface | `model/submodel.go` (`SubModel`) |
| Tree view | `model/tree.go` |
| Graph (Miller-column) view | `model/graph.go` |
| Raw pretty-printed view | `model/raw.go` |
| Search | `model/search.go` |
| jq filter view | `model/filter.go` |
| JSON parsing into the internal tree | `model/node.go` (`ParseJSON`) |
| JSON node → path/summary/native value | `model/node.go` (`Path`, `Summary`, `ToInterface`) |
| Schema export (`S` key, `--schema`) | `model/export.go` (`Node.Schema`) |
| LLM/compact-YAML export (`L` key, `--llm`) | `model/export.go` (`Node.CompactYAML`) |
| jq evaluation (filter view and `--query`) | `model/jq.go` |
| Clipboard writes | `clipboard/clipboard.go` |
| Colors and shared styles | `ui/colors.go` |
| Test fixtures | `testdata/` |
| Homebrew formula (generated) | `Formula/` |
| Release config | `.goreleaser.yml` |

## Development

### Prerequisites

- **Go:** 1.27 or later (see `go.mod`)
- **Build:** `make build`; **Lint:** `golangci-lint` (`make lint`)

### Common commands

| Action | Command |
|--------|---------|
| Build | `make build` (produces `./peep`) |
| Install to `$(PREFIX)/bin` | `make install` |
| Run tests | `make test` (`go test ./... -race`) |
| Vet | `make vet` |
| Format check | `make fmt` |
| Lint | `make lint` |
| Clean | `make clean` |

### Troubleshooting

- **Wrong Go version:** ensure `go version` is 1.27+.
- **Missing modules:** run `go mod tidy` at the repo root.
- **Clean build:** `go clean -cache` then rebuild.
- **Lint details:** run `golangci-lint run ./...` directly for full output; add `--fix` for auto-fixable issues.
